# ふたりログ — デザイン・UI/UX監査

調査日：2026-09-20。ホームを基準に、390×844のブラウザ表示・操作とソースを照合。今回の作業は調査のみで、製品コードは変更していない。

## 結論

ホームの「淡い背景・大きな余白・丸い面・ピンクの操作色・マスコット」は基準として使える。違和感が強いのはメモ画面とREPLAY。プラン詳細は同じ世界観に寄せられているが、重要情報の文字が小さく、操作と装飾の区別が弱い。

ただし、ホームのCSS自体も色の直接指定が多い。ホームのコードをそのままコピーするのではなく、ホームの見た目を共通部品と用途別トークンに定義し直す必要がある。

優先順位は、①実行できない・結果を誤解する導線、②入力消失・エラーからの復帰、③文字の読みやすさとボタン統一、④装飾色・角丸の整理。

## UI/UXの問題

### 先に直すべき項目

**U01 — 高：変更したいと入力できるのに、通常環境では送れない。**

場所：プラン詳細 → 「ここを変えたい」「プラン全体の希望を伝える」。入口は表示されるが、送信処理とボタンが `!fixturesEnabled()` で無効化される。「準備中」は入力欄の下にある。期待を持って入力した後に使えないと分かる構造。実画面はfixtureで確認、通常環境で無効になる点はソース確認。利用可能になるまで入口で明示するか、入力自体を開始させない。

根拠：[session-screen.tsx](/Users/kuakobayashi/work/futari-log/src/features/session/session-screen.tsx:103)

**U02 — 高：集合場所を空にできず、入力した地名と位置情報が一致する保証がない。**

日時場所ステップで「名古屋駅」を全消去すると、即座に同じ値が戻ることを実操作で確認。`form.meetName || 既定値` を入力値にも使っているため。さらに送信時の緯度経度は `me.demoLat/demoLng`、spotIdは名古屋駅の固定値で、名前だけが自由入力。場所選択としては不十分。実API側で補正されるかは未検証。空欄・placeholderと既定値を分け、場所検索結果の座標と名前を一緒に扱う。

根拠：[plan-form.tsx](/Users/kuakobayashi/work/futari-log/src/features/home/plan-form.tsx:90)、[送信内容](/Users/kuakobayashi/work/futari-log/src/features/home/plan-form.tsx:123)

**U03 — 高：メモの「次のデートに活かす」という期待と保存先が一致しない。**

追加はlocalStorageのみで、サーバーの記憶への登録処理はない。一方、元からある記憶の編集はAPIへの改訂要求。同じ一覧に並びながら意味が違う。新規ローカルメモには編集ボタンがなく、削除しかできない。「この端末に保存」の小さな注記だけでは、次のプランに使われるか分からない。ローカル下書きと有効な記憶を明示し、登録・編集の体験を揃える。

根拠：[memory-screen.tsx](/Users/kuakobayashi/work/futari-log/src/features/memory/memory-screen.tsx:25)

**U04 — 高：メモを保存すると「確認待ち」になるが、その先の導線がない。**

編集後は「変更内容を確認待ちにしました」と表示する実装。しかしこの画面には待機中の内容・承認操作・確認場所へのリンクがない。`useMemory`は候補を取得するが画面では利用していない。保存失敗と区別しづらい。承認が必要ならその場で次の操作を提示する。

根拠：[memory-screen.tsx](/Users/kuakobayashi/work/futari-log/src/features/memory/memory-screen.tsx:35)、[use-memory.ts](/Users/kuakobayashi/work/futari-log/src/client/hooks/use-memory.ts:7)

**U05 — 高：作成・振り返り・変更希望の入力を、シートを閉じるだけで失う。**

HomeSheetは背景クリック・Esc・閉じるで無条件に終了し、入力は各画面のローカルstateにある。下書き保存・変更検知がない。作成の最終ステップまで進んでEscで閉じられることを確認。入力途中の復元、または変更がある場合だけ破棄確認を付ける。

根拠：[home-sheet.tsx](/Users/kuakobayashi/work/futari-log/src/features/home/home-sheet.tsx:25)、[plan-form.tsx](/Users/kuakobayashi/work/futari-log/src/features/home/plan-form.tsx:72)

**U06 — 高：メモとREPLAYの通信失敗時に、復帰の操作がない。**

`useMemory`と`useReplay`の初回取得にcatchや表示用error stateがない。メモは読込中と空一覧を分けていないため、取得前から「まずはひとつメモを」の表示になり得る。REPLAYは取得失敗後も「読み込み中…」から進めない。メモ編集・削除にもpending/errorの制御がなく、連打や失敗への説明がない。通信障害は未注入で、ソースからの判断。共通のLoading / Empty / Error / Retryを設ける。

根拠：[use-memory.ts](/Users/kuakobayashi/work/futari-log/src/client/hooks/use-memory.ts:24)、[use-replay.ts](/Users/kuakobayashi/work/futari-log/src/client/hooks/use-replay.ts:12)

### 次に整理する項目

**U07 — 中：メモ未設定ページが行き止まり。**

`/memory`を直接開くと説明文だけで、タイトル、戻る、新しいプランを作る操作がない。ホーム内の空メモでも次の行動は説明だけ。ホームに戻る/作成するボタンを添える。実画面で確認。

根拠：[memory-screen.tsx](/Users/kuakobayashi/work/futari-log/src/features/memory/memory-screen.tsx:26)

**U08 — 中：承認時に、変更内容の比較が足りない。**

承認カードは「A → B」の要約のみで、下は現行プランのまま。変更後の時刻・予算・移動などを比較できない。下部には無効な「このプランで決める」が残る。どの操作が今必要かを固定フッターにも反映し、変更前後を見せる。fx-approvalで確認。

根拠：[session-screen.tsx](/Users/kuakobayashi/work/futari-log/src/features/session/session-screen.tsx:70)

**U09 — 中：エラーと無効ボタンの理由が離れている。**

生成失敗時に `validation FAIL` などの内部文言をそのまま表示する。上部に警告、下部に無効な確定ボタンがあり、スクロール位置によって対処が分からない。初回生成失敗にも「作り直せませんでした」を使う実装。利用者向けの説明と再試行/条件修正を近くに配置する。エラー表示はfixtureで確認。

根拠：[session-screen.tsx](/Users/kuakobayashi/work/futari-log/src/features/session/session-screen.tsx:69)

**U10 — 中：生成中に進捗・待ち続ける理由・離脱後の扱いが分からない。**

表示は実進捗イベントと連動していない。通常環境は4行とも「プランを準備しています」。作成直後のオーバーレイでは閉じるヘッダーが隠れる。所要時間は確証がなければ出さず、処理状態・戻った後も継続するか・長時間時の対応を説明する。

根拠：[plan-loading.tsx](/Users/kuakobayashi/work/futari-log/src/features/session/plan-loading.tsx:16)、[plan-form.tsx](/Users/kuakobayashi/work/futari-log/src/features/home/plan-form.tsx:196)

大きな施設カードの写真はカテゴリごとのイメージ。「イメージ」の注記は8px。予定間の空き時間を「移動・ひと休み」として出すが、経路案内・実際の移動時間とは区別が弱い。写真の注記を読みやすくし、移動方法や地図への入口を検討する。実画面と計算処理を確認。

## 現行画面と分けて扱うもの

- `SessionDetails`：現行の `/sessions/[id]` は `SessionScreen` を使っており、この旧画面への参照はない。カード3列・内部状態・シナリオ注入など旧検証UIが残る。実ユーザー画面の不具合として数えず、削除または開発専用化の対象。
- 記録一覧/提案一覧：描画分岐はあるが入口がない。必要なら導線を設計して公開し、不要ならコードを整理する。
- 開発用一覧：製品画面と同じ幅にする必要はない。ただし実部品を使うこと、独自の見本を複製しないことは維持する。単一箇所・未使用の表示は静的JSX解析であり、実ユーザーの利用率ではない。
- 今回追加した開発ボタンが小画面でコンテンツに重なる箇所は確認したが、本番には表示されないため製品UXの問題とは分ける。

## 修正のまとまり

1. **機能と案内の一致**：変更送信、場所選択、メモの保存・反映・承認、行き止まり、通信失敗の復帰。
2. **共通部品**：Button / IconButton / DateCreateButton に加え、入力欄、戻るリンク、通知、空状態、確認カードを共通化。場当たり的なページCSS上書きをなくす。
3. **共通の視覚基準**：操作色・本文・補足・背景・枠線・状態色、文字サイズ、角丸、タップ領域を決める。マスコットの感情色や写真は別枠。
4. **画面単位で移行**：メモ → プラン詳細と状態表示 → 作成フォーム → 振り返り/ホーム微調整。REPLAYと旧画面は利用者向けに残すかを先に決める。
