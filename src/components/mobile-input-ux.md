# スマホの入力とモーダル

調査・実装: 2026-09-21。対象は Web（iOS Safari / Chrome、Android Chrome、ホーム画面起動）。

## 調査から採用した方針

- キーボード表示で縮むのは Visual Viewport であり、Layout Viewport や `dvh` が同じように縮むとは限らない。`100dvh` と `bottom: 0` だけで入力領域を保証しない。[Chrome の説明](https://developer.chrome.com/blog/viewport-resize-behavior)
- WebKit にはキーボードの開閉アニメーションが終わるまで viewport 更新が遅れる報告もある。固定ミリ秒の再スクロールを重ねない。[WebKit の報告](https://bugs.webkit.org/show_bug.cgi?id=265578)
- モーダルはフォーカスを内部に保ち、閉じたら起点に戻す。開いた瞬間に本文が飛ぶ初期フォーカスは避ける。[WAI-ARIA Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## ライブラリ比較

| 候補 | 判断 |
| --- | --- |
| [React Aria Modal](https://react-aria.adobe.com/Modal) | 採用。フォーカス・スクロール抑止と Visual Viewport の CSS 変数を提供。ドラッグを必要としない既存モーダルに適する。 |
| [React Modal Sheet](https://github.com/Temzasse/react-modal-sheet) | キーボード回避機能あり。Motion が必要で、スナップ・ドラッグ式シートが必要になった際の候補。 |
| [Vaul](https://github.com/emilkowalski/vaul) | 公式 README に unmaintained の記載があるため今回の新規採用は見送り。 |
| [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) | アクセシブルなモーダルの候補。ただし置き換えるだけで可視領域や入力レイアウトまで解決するとは扱わない。 |

React Aria 1.21.1 のインストール済み実装も確認。モバイル WebKit 用のスクロール制御、入力間の移動、キーボードの Done 操作、ピンチズームへの処理がある。ライブラリにも OS ごとの差があるため実機検証は必要。

## 実装ルール

1. 文字・数値・時刻は `TextInput`、複数行は `TextArea`、ネイティブ選択は `SelectInput`。ラジオ・チェックボックスは対象外。ref / IME / 選択 / autofill はネイティブに委ねる。
2. 入力文字は最小16px、操作領域は最小44px。大きい文字は `--input-font-size` で指定する。ズーム禁止の viewport 設定は加えない。
3. 新しいモーダルも `ModalSurface` を使う。独自の body lock、focus trap、visualViewport の位置補正を重ねない。
4. モーダルの高さは React Aria の `--visual-viewport-height` を使う。キーボード開閉時の height / bottom をアニメーションしない。
5. 常時スクロールさせる領域は原則一つ。メモは追加欄と一覧を一緒にスクロール。プランは本文だけスクロールし、非常に高さが低い場合は全体スクロールへ切り替える。
6. 入力 focus、検索候補の更新ごとに `scrollIntoView` しない。「希望を書く」の明示操作のみ、同期して入力を表示して focus する。共通モーダルは `useVisibleModalInput` で focus 中の欄と祖先のサイズ変更を監視し、レイアウト確定後に隠れた分だけ内部スクロールを補正する。見えている欄、手動スクロール、拡大操作には追従しない。
7. 数値の予算には `inputMode="numeric"`。複数行入力の Enter を送信や blur に置き換えない。開いた瞬間に textarea を autoFocus しない。
8. 「次へ」「保存」をキーボード表示判定だけで非表示にしない。狭い領域では装飾を減らし、操作までスクロール可能にする。

## 適用範囲

| 画面 | 入力 |
| --- | --- |
| プラン作成 | 自分の希望、集合・解散場所、開始・終了選択、合計予算と内訳、相手の希望、固定予定名と時刻 |
| ホームの振り返り | タイトル、本文 |
| メモ（ページ・モーダル共通） | 追加、保存済みメモの編集 |
| プランの変更依頼 | 希望の本文 |
| セッション詳細 | 振り返りのメモ |
| 開発カタログ | サンプル入力、検索、絞り込み |

## 実機での合格条件

- iOS Safari / iOS Chrome / Android Chrome と、必要ならホーム画面起動で確認。PC の高さ変更はレイアウト検証であり OS キーボード再現ではない。
- 同じ入力欄で開く→閉じる→再度開くを繰り返しても、位置ずれや下端の空白が蓄積しない。
- 日本語変換、改行、選択・コピー、長文、キーボードの次へ／前へ／完了で入力内容を失わない。
- 一覧下方の編集欄、任意項目、数値・時刻のピッカーにも移動でき、保存・次へまで到達できる。
- キーボードを閉じてから背景をスクロールできる。モーダル内操作では背景が動かない。
- 縦／横画面、ブラウザのバー開閉、拡大表示、外付けキーボードでもフォーカスと操作を失わない。
- 破棄確認をキャンセルすると元のモーダルへ戻り、閉じると起点へフォーカスが戻る。

## 今回の検証記録

- TypeScript、変更ソースの ESLint、境界チェック、diff の空白チェックを通過。
- ブラウザで390×420・390×300のレイアウトを検証。メモ編集欄と保存操作、希望の入力、集合場所の候補選択、予算・複数行入力に到達できることを確認。
- 破棄確認のキャンセルで入力内容を保持し、完全に閉じると起点のボタンへ focus と背景スクロールが戻ることを確認。
- 通常のメモページでも16pxの入力と文書スクロールを確認。検証タブの console error / warning はなし。
- iPhone / Android の実キーボード、IME、ピンチズーム、ホーム画面起動は未検証。上の実機合格条件を満たしたとはまだ扱わない。
- 追加の実機報告で「希望を書く」の focus 後に入力欄が隠れる不具合を確認。最初から低い画面で focus する検証だけでは不十分だった。focus → viewport縮小 → コンテナ再配置の順序を追加し、入力欄とスクロール領域の実座標を比較する。
- リポジトリ全体の lint は動画制作用 Python 環境内の JS まで走査するため中断し、変更ソースへ限定した。
